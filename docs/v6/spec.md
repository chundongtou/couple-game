## 0. V6.1 变更（2026-11-17，用户试玩反馈）

> 背景：V6.0.0 上线后用户试玩反馈「一局结束太快」，并要求「一个人四架飞机全部到终点后结束；开局摇 6 起飞有一家非常难」。
> 唯一协调口径：`docs/v6/impl-freeze-v6.1.md`（与 V6.0 的 `impl-freeze.md`、与本文件其余章节冲突处，都以它与本节为准）。本节只写**对 V6.0 的增量**，未提到的条目沿用 V6.0。

1. **结束条件改为飞行棋胜负**：任意一方把**本局全部飞机**送进终点（`home:<color>:goal`）→ 本局收尾。快局每人 **2 架**、长夜每人 **4 架**。
   - **不再**用「合计处理题卡数达到目标」或「心动值达到目标」结束；`targetCards / targetHeat` 字段保留但只作历史兼容，不参与判定。
   - 去掉 V6.0 的「长夜任一架进终点就结束」。
2. **起飞保底**：仍保留「掷出 6 才起飞」；但同一玩家**连续 2 个自己的回合都没掷出 6**（且该方所有未到家的飞机都在机坪），**第 3 个自己的回合任意点数都可起飞**；起飞成功后计数清零；掷出 6 也清零。
   - 保底提示：`view.takeoff.pity === true` 时，掷骰前显示「连续两次没起飞 · 这一掷任意点数保底起飞」；可观察位 `data-test="takeoff-pity"`。
3. **模式时长与门厅文案**：快局约 **15–25 分钟**、长夜约 **30–50 分钟**；模式卡改为「先送完 2 架飞机 · 约 15–25 分钟 · 每人 2 架」/「先送完 4 架飞机 · 约 30–50 分钟 · 每人 4 架」，**不再显示「目标 4/8 张题卡」**；规则速览 6 条同步（6 起飞含保底、一方全部到家就收尾）。
4. **收尾与回顾**：赢家出现后仍发 2 张「今晚最后一张」（各给一人），都处理 / 放过后进「今晚回顾」；主桌与回顾写「**<姓名> 先到家**」，回顾另显示「**已到家 X/Y**」；不出现羞辱性输赢文案（不加减心动值、不惩罚输家）。
5. **主桌状态条**：不再显示「第 N/目标 张」，改为可读到双方到家数（如「红 0/2 · 黄 0/2 · 心动值 X · 连击 Y」）；`data-test="status-cards"` 节点保留，新增 `status-home`、`takeoff-pity`、`winner-text`。
6. **兼容**：旧档（`session.v` 为 `1` 或 `2`）由 `validate()` 补 `takeoffMiss: {a:0,b:0}` 默认 0，可原样续玩；`ledger.ending` 收敛为 `'win-a' | 'win-b' | 'safe'`，旧档 `'shared'` 仅按兼容文案展示（见 §4 F2）。
7. **验收重排**：§4 E2/E3、§7 主路径、M1/M6 口径按「构造一方全到家」重写；QA 用例与报告以 `reports/v6/` 为准（本文不写具体测试数字）。

## 0.1 V6.2 变更（2026-11-18，沉浸主桌「夜航客舱」）

> 背景：用户试玩后反馈「画面要身临其境 + 动画」，并拍板世界观 = **机舱**、镜头 = **全动态（跟拍 + 震动）**、范围 = **直接全量**。
> 唯一协调口径：`docs/v6/impl-freeze-cabin.md`。**本节只写表现层增量**：规则、数值、题库、存档结构与 V6.1 完全一致，不因本版改变任何一局的结果或续玩方式。

### 0.1.1 范围与不变量

1. **新增场景**：主桌 `.v6-table` 内新增全屏 `.v6-cabin` 场景层（`data-test="cabin"`）；`App.CabinScene` 在层内挂 `.cabin-root[data-test="cabin-scene"]`，内容为舱壁 / 两扇舷窗 / 云星 Canvas / 小桌板 / 阅读灯 / 前景暗角。
2. **场景不参与玩法**：场景是装饰层（`aria-hidden`、`pointer-events:none`），不改变棋盘 52 格、机坪、航线、HUD、行动区、题卡、安全词的位置与点击路径。
3. **新增全动态镜头**：掷骰推近、走子/起飞/跳/飞跟拍、击落震动 + 闪白、叠机推近、换手左右移、题卡/小游戏拉远压暗、热度变暖、收家拉远 + 日出；镜头只改 `.v6-board` 的 `transform`，不改布局。
4. **reduced 优先**：系统 `prefers-reduced-motion: reduce` 或设置「减少动画」命中时，无镜头移动、无震动、无闪白/波纹/心形脉冲，场景静态绘制、以 reduced 挂载时粒子减半；只保留透明度类过渡。
5. **性能与降级**：DPR 有上限、空闲约 30fps、页面隐藏暂停、动画结束释放 rAF；`App.CabinScene` 缺失 / `mount` 失败 / `play` 抛错都不阻塞棋局。
6. **版本**：`App.version = "6.2.0"`；构建产物包含 `src/view/cabin.js`（在 `ui/screens/table.js` 之前）。

## 0.2 V7 变更（2026-11-18，云海机舱 · 45° 格子剧场）

> 背景：用户拍板「**第三人称跟拍 + 第一人称 POV 两者都要**」；主题 = **云海机舱**；小熊 = **随主题换装**；每回合 **5–8 秒**；**直接全量**。
> 唯一协调口径：`docs/v7/impl-freeze.md`。**本节只写表现层增量**：规则、数值、题库、存档结构、边界与安全词与 V6.2 完全一致，不因本版改变任何一局的结果或续玩方式。

### 0.2.1 范围与不变量

1. **每回合镜头链**：`overview → roll →（多子可走时回 overview 等选子）→ pov → chase → land → cell45 → bear → return`；状态写在 `.v6-table` 的 `data-cinema-state` 上；整条 **5–8 秒**（不含答题）。
2. **第一人称 POV + 第三人称跟拍**：POV 是固定机位的前景（机头 / 机翼 / 速度线 / 云掠过 + 棋盘倾斜）；跟拍按目标格方向平移 / 缩放并让目标格发光；落地有尘土 / 涟漪 / 轻震。**不做自由视角**，不改棋盘可点区域。
3. **45° 格子舞台（CellStage）**：落在题卡 / 命运 / 收尾 / 进航时，棋盘压暗、目标格升到 45° 舞台；左列 45° 格面 + 小熊，右列暖纸内容卡。430 宽约 28% / 68%，320 宽约 22% / 74%；长文本卡内滚动、按钮固定；安全词与暂停永远在舞台之上。
4. **向导小熊**：单只程序化 SVG，随主题换装（`pilot / starlight / paper`）；探头 / 眨眼 / 耳朵抖 / 举牌；做了→点头、放过→放下牌子（不评判）；`aria-hidden`，不承载可读文本。
5. **三个主题**：`cloud`（云海机舱，默认）/ `star`（星轨夜航）/ `paper`（纸雕童话）；门厅「今晚的桌面」三选一（`data-test="theme-cloud|star|paper"`），设置页也可切换；写 `settings.theme`，刷新记住；主题与玩家预设（名字 / 颜色 / 尺度）独立，可组合。
6. **主题只改画面**：不改 52 格拓扑、题卡内容、规则、边界与安全词；主桌机舱 / 棋盘本体的固定配色不在本版重绘（见 §0.2.3）。
7. **快进**：镜头动画中显示「快进」（`data-test="cinema-skip"`）；点按后当前阶段立即到终态，后续阶段各约 130ms 直接到终态，直到回 `overview`；不影响棋局结果。
8. **reduced**：系统 `prefers-reduced-motion` 或设置「减少动画」命中时，无 POV / 跟拍 / 震动 / 闪白 / transform；各阶段 160ms 级淡入，格子舞台静态出现；`data-cinema-reduced="1"`、主桌 `data-reduced="1"`。
9. **表现层解耦与降级**：`App.Cinema` 独占 `boardEl.transform`（`CabinScene.setCameraEnabled(false)` 后退到场景视差 / 灯光）；`CellStage` 缺失 → 回退 `PromptCard`；`Themes` 缺失 → `cloud`；`Bear` 缺失 → 无熊布局；任一层失败都不阻塞棋局。
10. **构建 / 版本**：`App.version = "7.0.0"`；`app/index.template.html` 的 title/og 为 V7；`manifest.webmanifest` name 为 V7；构建模块表按 `themes → bear → … → cabin → cinema → … → prompt-card → cell-stage → table` 排列，并有顺序闸门。
11. **性能**：首屏预算沿用 ADR-012（index gzip ≤140KB；首屏 ≤180KB）；20 回合连续走子长帧（>25ms）≤5%；页面隐藏暂停；主路径 0 pageerror / 0 console error。
12. **V6 回归**：V6.1 / V6.2 全部 E2E 用例与引擎单测必须保持全绿；`couple2.*` 键名、`v:2` 存档结构、`takeoffMiss` 兼容、安全词机制不变。

## 0.3 V8 变更（2026-11-19，真 3D 主桌）

> 背景：用户拍板「主桌全部 3D；摇骰后棋盘放大、视角落到飞机；**飞机固定在屏幕上，棋盘旋转/平移**制造前进错觉；到目标格后 45° 格子 + 3D 小熊 + 右侧内容卡」。

> 唯一协调口径：`docs/v8/impl-freeze.md`；3D 模块说明：`app/src/view/board3d/README.md`。**本节只写表现层增量**：规则、数值、题库、存档结构、边界与安全词与 V7 完全一致，不因本版改变任何一局的结果或续玩方式。

### 0.3.1 范围与不变量

1. **默认 auto**：`settings.board3d` 三档 `auto`（默认）/ `off`（始终 V7）/ `on`（强制尝试 3D）；`auto` 以 **WebGL2 可用**为硬条件进 3D，**「减少动画」不再回退 V7**（V8.1 起为静态 3D）。`table.js` / `settings.js` 各一个 `BOARD3D_DEFAULT`，用户手动选过按用户值。
2. **3D 挂载**：`App.Board3D.mount(host, opts) -> Promise<inst|null>`；成功时 `.v6-table` 为 `data-board3d="on"`、宿主内有 3D layer + canvas、`data-3d-ready="1"`、`_debug().mounted=true`、`three=r180`、`version=v8-prod-3d-1`；V7 棋盘视觉层（`.v6-board` / Cinema / Cabin）不再可见，HUD / 题卡 / 暂停 / 安全词保持 DOM 且可点。
3. **3D 镜头链**：`overview(idle) → roll → focus → fly → land → cell45 → bear → return`；`data-3d-phase` 可断言；题卡/小游戏打开时停在 `bear` 并 `holding=true`，处理后 `returnToOverview()` 回 `idle`。
4. **固定飞机飞行**：fly 期间相机停在 focus 位姿（不再移动）、飞机固定在屏幕中心（世界原点上方），棋盘组按目标格位姿旋转（`theta`）+ 平移（`tx/tz`）制造前进错觉；逐格推进（环 165ms/格、航线 190ms/格；起飞 900ms；跳 540ms / 飞 840ms）；`_debug().probe.lock` 记录 NDC 采样 `samples / maxAbsX / maxAbsY`。
5. **45° 格子 + 3D 小熊 + 右侧 DOM 卡**：目标格升起 `STAGE_RISE=1.50`、方位 24°；3D 小熊在格子左后探头；题卡**只出右侧 DOM 卡**（`.v6-table.v8-3d-card`、`.cs-left{display:none}`、`.cs-card` 在第 2 列），左侧留给 3D 格子/小熊；卡片文字正向、长文卡内滚动、不挡暂停与安全词。
6. **chunk 懒加载**：three 独立 chunk（esbuild IIFE / target es2018），index 只注入 `window.__BOARD3D_URL`，**无 `<script src>` / preload**；首屏不请求；同源先 fetch 再内联执行（404 不留 console error），整页只尝试一次、失败不重试、9s 超时；chunk 按内容哈希命名并进 SW PRECACHE，离线可用。
7. **失败回落 V7**：`off` / 无 WebGL2 / chunk 404 / 模块未接上 / mount 返回 null / mount 抛错或 reject / 载入后异常——全部回落完整 V7（BoardView + Cinema + CabinScene + CellStage），降级原因写 `data-board3d="v7"` + `data-board3d-reason`，不白屏、不阻塞棋局。
8. **reduced**：系统 `prefers-reduced-motion` 或设置「减少动画」命中时，3D 为**静态棋盘**（只画一帧 / 落终态，无 focus/fly/land/cell45/bear 镜头、无速度线 / 震动），`data-3d-reduced="1"`；`auto` 下仍是 3D，不回 V7。
9. **3D 图例（V8.2）**：3D 模式 HUD 有「图例」入口（`data-test="board3d-legend"`，V7 不显示），面板 11 行（`真/敢/触/缘/温/轮/起/飞/停/归/·`，`data-test="board3d-legend-row"`），挂在棋盘区且不遮暂停 / 安全词；打开时收起底部行动区；题卡上来 / 3D 回落时自动收起。
10. **设备自检（V8.2）**：设置页「3D 主桌」下只读一行（`data-test="settings-board3d-status"`），展示 WebGL2 / reduced / 当前档位 / 上次 mount 结果与原因；机读属性 `data-webgl2 / data-reduced / data-board3d-set / data-board3d-mount / data-board3d-reason`；不写设置、不触发挂载。
11. **320–430**：320×568 / 390×844 / 430×932 无横向溢出，canvas 跟随宿主尺寸，`distForCover` 按纵横比自适应；HUD / 掷骰 / 图例 / 安全词仍可点；题卡只出右侧卡时左列保持 10–16px 安全距。
12. **性能与预算**：首屏预算沿用 ADR-012（index gzip ≤140KB；首屏 ≤180KB）；3D chunk 懒加载、不计入首屏；chunk 体积按 **≤160KB gzip** 验收（冻结单 140KB 在 three r180 下不可达，见 §0.3.3）；`--check` 发布门 37 项。
13. **V7 回归**：V7 全部 E2E 用例、引擎单测、存档结构（`v:2`）、`takeoffMiss` 兼容、安全词机制保持不变；V8 与 V7 共用同一套规则与题库。

## 1. 目标与成功口径

### 1.1 一句话目标

让一对情侣在**一部手机、一个晚上、随时可能被打断**的条件下，能从「打开」到「今晚收尾」走完一局，全程知道「轮到谁、掷了几点、这张题给谁、我能不能先停下」，并且**任何一次「放过」都不会让今晚变糟或走不下去**。

### 1.2 可量化的成功口径（用于 V6 验收，不用于宣传）

## 2. 目标用户与场景

### 2.1 用户

- **一对情侣/伴侣**，两人共同使用**同一部手机**；非技术用户，不会看说明文档，靠界面自解释。
- 关系阶段与尺度偏好不同；对「露骨」「被拒绝」「被评判」敏感。**双方自愿**是前提。
- 可能一方主导操作（拿着手机的人），另一方在旁看屏幕/被要求做。
- 夜间、私密、室内（床/沙发），常伴低光；可能中途被打断（家人、消息、困了、情绪变化）。

### 2.2 关键场景

| 场景 | 描述 | 设计含义 |
|---|---|---|
| S1 第一次打开 | 不知道玩法，30 秒内要能开局 | 开局页首屏可完成；规则一屏可读；不需要注册 |
| S2 快局（工作日夜） | 15–25 分钟，想玩一点就睡 | 快局模式：每人 2 架 + 先送完 2 架收尾 + 合作收尾卡 |
| S3 长夜（周末） | 30–50 分钟，愿意走完整盘 | 长夜模式：每人 4 架 + 先送完 4 架收尾 + 完整棋盘 |
| S4 中途被打断 | 有人敲门/孩子醒了/一方不想继续 | 安全词/暂停随时可达；暂停不丢进度；可「今晚就到这」 |
| S5 一方明确不做某类 | 想加边界，不想解释 | 开局 6 个预设 + 自定义；**中途也能加**；边界优先 |
| S6 只想放过这一张 | 不想做但也不想破坏气氛 | 放过不惩罚：不扣心动、不阻断进军、不丢奖励、不算失败 |
| S7 网络差/没网 | 床上信号差；已装到桌面 | 离线可开局、可续玩、可收尾 |

### 2.3 非目标用户

- 单人自娱（V6 不做 AI/单人模式）、异地联机（同一部手机）、多人群玩（只支持 2 人）、未成年向内容。

## 5. 玩法改动提案（P0/P1 汇总与规则细节）

> 以下「数值」是产品建议值，**不是已定案**；实现后允许通过配置调整，但验收按本节的数值断言。

### 5.1 心动值（P0，替代「没有进度」）

- 共同值 0–100，不按人分；任何操作不下降。
- 计分：题卡「做了」+8；「放过」+3（正向，表示诚实边界）；小游戏完成 +5；小游戏跳过 +0；收尾卡「做了」+10、「放过」+3；击落/叠机等棋类事件 +0（避免把「攻击对方」变成奖励）。
- 阶段文案（新增 UI 文案，非题库）：0–19「灯刚亮」/ 20–39「有点热」/ 40–59「靠近了」/ 60–79「很近了」/ 80–100「今晚可以更近」。
- 界面：主桌状态条、暂停页、回顾页三处显示同一数值与阶段名。

### 5.2 连击（P1，奖励而非惩罚）

- 两人合计连续「做了」计数；3 张触发一次「双人选卡」（2 张同尺度卡二选一，另一张放回）。
- 放过**不清零**、不扣心动；只是不增加连击。连续 6 张再触发一次（可叠加）。
- 连击数常驻显示；触发时给一次 ≤1.5s 的反馈（文本 + 轻音效），不阻塞操作。

### 5.3 二选一命运格（P1，给棋盘中段变化）

- 棋盘 2 个「命运」格；落上后同时展示 2 张不同池的卡（如真心话 + 大冒险 / 靠近 + 真心话），二选一；另一张放回池子。
- 选择/不选都不惩罚；「今晚先不选」= 直接回主桌，不扣心动、不算失败。
- 命运格是否计入 `cardsProcessed` 必须在界面写明（建议不计入，作为节奏彩蛋；V6.1 起它不影响结束）。
- 需用户确认是否接受新增格类型（见 Q1）。

### 5.4 先到家收尾（P0，V6.1 改为飞行棋胜负）

- 收尾条件：任意一方**本局全部飞机**到达终点（快局每人 2 架 / 长夜每人 4 架）。判定发生在最后一次走子 / 题卡结算之后（`afterAction` / `resolvePrompt` 之后）。
- 题卡张数与心动值**不再**触发结束；`targetCards / targetHeat` 字段保留但只作历史兼容（旧 UI / 旧测试引用），不参与 `shouldEnd`。
- 进入「今晚最后一段」：从现有 `ending` 池（mild 权重）抽 2 张收尾卡，按顺序各标归属，两人各处理一张（可放过）。
- 结束：回顾页不判定输赢，写「<姓名> 先到家」+「已到家 X/Y」；ledger `ending` 为 `'win-a' / 'win-b' / 'safe'`，`stats.planesHome` 记录双方到家数。
- 不惩罚输家：赢家不额外加心动值，输家不扣；「输/赢/胜/负」不出现在任何界面（「先到家」不算判定词）。

### 5.5 今晚就到这（P0）

- 任意时刻（暂停页）可选；直接进入收尾/回顾，不判定输赢，记录全部保留。
- 与安全词的区别：安全词=立即停止当前互动（可能只是暂停）；「今晚就到这」= 主动结束并归档。两者都不惩罚。

### 5.6 今晚回顾（P0）

- 见 F2 的 6 类信息；题卡明细可展开；历史最多保留 60 局（沿用现状）。
- 隐私：只在本机；可导出 JSON；不生成公开链接。

### 5.7 快局/长夜时长（P0/P1）

- 快局：每人 2 架，预计 **15–25 分钟**；长夜：每人 4 架，预计 **30–50 分钟**（用户拍板口径，见 `docs/v6/impl-freeze-v6.1.md` §3.1）。一局时长由「一方全部到家」决定，不再由题卡数决定。
- 历史依据：V6.0 用现状模拟（`shots/v6/analyze.json`：4 架约 94.2 次掷骰 / 32.6 张题卡，2 架约 46.3 次 / 15.3 张）把结束条件压成「目标题卡数」，门厅写 8–12 / 25–40 分钟。V6.1 试玩反馈「结束太快」，故回退为全到家结束，门厅时长按用户拍板的 15–25 / 30–50 分钟展示。
- 实际时长以 QA 报告与真机试玩为准（`reports/v6/`），本文不预写具体测量值。

### 5.8 不惩罚「放过」原则（P0 红线，逐条可测）

1. 心动值不减少（可 +3）。
2. 不阻断进终点：进航题放过 → 照样进军（取消现状 `skipHomeEntryBlocksEntry` 的阻断语义）。
3. 不丢奖励步：叠机题放过 → 仍执行固定奖励步（或把奖励与题卡解耦）。
4. 连击不清零。
5. 回顾只写「今晚先放过」，不写失败/未完成/扣分。
6. 放过不影响结束判定：V6.1 只看「一方全部飞机到家」，题卡张数不再参与，所以全放过局同样能收尾（修 AUD-03 的「永不结束」）。

### 5.9 P2（登记，不在 V6 范围）

| 提案 | 说明 | 为什么是 P2 |
|---|---|---|
| 回顾页生成「今晚卡片图」 | 本机生成一张可保存的图（不含露骨内容，只有日期/统计/几条原文） | 需要视觉与排版设计，且涉及隐私默认值；P0 先保证文字回顾 |
| 长夜保留「谁先到家」彩蛋 | 结束页角落一行小字，不影响收尾 | 与合作式收尾方向有张力，等 Q3 拍板 |
| 横屏/平板布局 | 大屏两栏（棋盘+题卡） | 需单独布局与测试，P0 只保竖屏 320–430 |
| 棋盘皮肤/音效主题 | 玩家可选 | 纯装饰，不影响主路径 |
| 成就/里程碑 | 「第一次放过」「连续 5 张」等 | 容易变成变相惩罚/攀比，先观察 |
| 多语言 | 英文/繁中 | 无用户需求证据，且文案含大量口语 |

### 6.2 动画与反馈要求（可测）

- `AN-1` 掷骰：结果文本在 **≤800ms** 出现；整段骰子动画 **≤1.6s**；动画可被「减少动画」压到 ≤100ms。
- `AN-2` 走子：单次移动动画 **≤2.0s**（多步合计）；落点格名在走子结束 **≤500ms** 出现；P1 提供「快进」跳过剩余动画。
- `AN-3` 题卡：出现动画 **≤400ms**；出现时不影响安全词可点；reduced-motion 时 ≤100ms 或无动画。
- `AN-4` 反馈：任何「做了/放过/小游戏完成/暂停」操作在 **≤500ms** 内有文本反馈（toast 或状态条变化），不依赖动画存在。
- `AN-5` 动画不阻塞输入：除 S2/S4 的防连点外，暂停与安全词在任何动画期间都可触发（安全词优先级最高）。
- `AN-6` 音效/震动可关；关闭后所有状态文本仍完整（不靠声音传达信息）。

## 7. P0 主路径与点击预算（≤20 次点击的验收路径）

**前提**：快局（每人 2 架）、固定种子、注入骰子（`window.__V6_TEST__.forceDie`）、**测试侧构造「一方差一步全到家」的局面**。
V6.1 起结束条件是「一方全部飞机到家」，一局自然对局约 40+ 次掷骰，不可能压进 20 次点击；因此本路径用「注入局面」来验证**流程与反馈**（门厅 → 主桌 → 掷骰 → 选子 → 到家 → 先到家 → 两张收尾卡 → 回顾 → 保存），20 次是「流程点击不膨胀」的护栏，不代表自然对局长度。注入方式：验收脚本在**第 2 步后**写 `couple2.session`（把 a 方两架分别放到航线第 4 格与最后一格，b 方留机坪；该操作不计点击），刷新页面后走「继续今晚飞行棋」。

| 步 | 点击 | 操作 | 期望可断言结果 |
|---|---|---|---|
| 1 | 1 | 开局页点「快局」 | 模式卡文本含「先送完 2 架飞机 · 约 15–25 分钟 · 每人 2 架」，不再出现「目标 4 张题卡」 |
| 2 | 2 | 点「摆上棋盘」（role=开始） | 进入主桌（`data-screen=table`），状态条「红 0/2 · 黄 0/2 · 心动值 0 · 连击 0」，`planeCount=2` |
| 3 | 3 | （注入局面后刷新）点「继续今晚飞行棋」 | 回到主桌，回合=先手方，状态条仍是「红 0/2 · 黄 0/2」 |
| 4 | 4 | 点「掷骰」（注入 1 点） | ≤800ms 出现「掷出 1」；两架都可走 → 出现文字选子按钮（`choose-piece`） |
| 5 | 5 | 点「红 · 第 2 架 · 沿航线走」（航线最后一格那架） | 该架进终点，状态条「红 1/2」；换手到对方 |
| 6 | 6 | 点「掷骰」（注入 1 点） | 对方全在机坪、无合法走子 → ≤800ms 出现「没有飞机能动，换 <姓名> 掷骰」并自动换回；不增加额外点击 |
| 7 | 7 | 点「掷骰」（注入 2 点） | 唯一可走的一架自动走到终点 → 状态条「红 2/2」；≤1s 出现「今晚最后一段」，主桌出现「<姓名> 先到家」（`data-test=winner-text`） |
| 8 | 8 | 第 1 张收尾卡点「做了」 | 心动值 +10；收尾卡 kicker「今晚最后一段 · 第 1/2 张 · 给 {name}」 |
| 9 | 9 | 第 2 张收尾卡点「做了」 | ≤500ms 出现「今晚完成了」，随后进入今晚回顾（`data-screen=ledger`） |
| 10 | 10 | 回顾页点「保存到以前的夜」 | `couple2.history` 里有本局且只有一条（实现可能在进入回顾时已自动归档，点击是幂等的——不强求跳列表）；总点击 **10 ≤ 20** |

补充：
- 若第 4 步注入的点数让「两架都可走」变成「只有一架可走」，则第 5 步不增加点击（引擎在单子可走时自动走）；本预算的上限仍为 20。
- 若掷骰无合法走子，**不增加点击**，只出现 B2 提示并自动换人。
- 该路径不含「小游戏」「换卡」「暂停」「保底起飞」，它们由 P0 的其他用例单独验收（保底见 §9 第 3 条与 `reports/v6/qa-e2e.md`）。
- 本路径已在引擎侧用脚本走通（DOC 自查：注入 `home:<color>:3` / `home:<color>:4` 后 `roll(1) → move → roll(1) → roll(2)` → 事件顺序 `dice → move → win → prompt → ending-start`，两张收尾卡后 `phase='ended'`、`ledger.ending='win-a'`、`stats.planesHome={a:2,b:0}`）；浏览器侧以 QA 报告为准。

## 9. 测试与验收策略（PA 视角）

1. **每条需求都有 AC**；AC 必须能被 QA 写成一条浏览器断言或引擎单测（文本/可见性/点击计数/时间阈值/数值）。
2. **引擎先行**：`qa/rebuild/flight-engine.test.mjs` 必须全绿（V6.0 的旧用例里「题卡数/心动值触发收尾」已按 V6.1 改为「不触发」或改为注入「一方全部到家」）。V6.1 必须有的引擎用例：① 一方 2 架 / 4 架全部到家 → `phase=ended`、`winnerId` 正确、`ledger.ending='win-a/b'`、`stats.planesHome` 正确、两张收尾卡；② 题卡做到 20 张但未全部到家 → **不结束**；heat 到 100 但未全部到家 → **不结束**；③ 连续 2 个自己的回合非 6 且全在机坪 → 第 3 个回合任意点数可起飞，起飞后 `takeoffMiss=0`，掷 6 也清零；④ 旧档（`v:1`/`v:2`）缺 `takeoffMiss` → `validate()` 补 `{a:0,b:0}` 且可续玩。
3. **浏览器主路径**：按 §7（注入局面 + 注入骰子）跑 3 种视口（360/390/430），断言每一步；另用 E2E 覆盖「起飞保底提示 `data-test=takeoff-pity`」与「`data-test=winner-text` 显示「<姓名> 先到家」」；断言 `window.onerror` 计数为 0（H6）。
4. **回归红线**（每次都跑，不允许退化）：
   - 安全词在 7 个屏幕可达且不遮挡（B4）；
   - 题卡 100% 带人名（C1）；
   - 放过不阻断进军；全放过局也能靠「一方全部到家」收尾（C2/E3）；
   - 边界过滤 100 次抽题无命中（H5）；
   - 刷新后可续玩（A6）；
   - 断网可开局/收尾（H3）；
   - 起飞保底不越界：第 2 个自己的回合不提前起飞，第 3 个回合才保底（§4 边界）。
