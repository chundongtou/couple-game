## 1. 目标与成功口径

### 1.1 一句话目标

让一对情侣在**一部手机、一个晚上、随时可能被打断**的条件下，能从「打开」到「今晚收尾」走完一局，全程知道「轮到谁、掷了几点、这张题给谁、我能不能先停下」，并且**任何一次「放过」都不会让今晚变糟或走不下去**。

### 1.2 可量化的成功口径（用于 V6 验收，不用于宣传）

| # | 口径 | 现状（audit 实测） | V6 目标 |
|---|---|---|---|
| M1 | P0 主路径（开局→掷骰→题卡→结束）完成所需点击 | 不可完成（离开被挡、无收尾路径；全放过对局 400 回合不结束） | **≤20 次点击**（固定种子 + 快局，见 §7） |
| M2 | 掷骰后玩家能读到点数的时间 | 无文字点数（只能看 3D 骰） | 掷骰动作后 **≤800ms** 出现点数文本 |
| M3 | 无棋可走时的说明 | 无提示，静默换人 | **≤800ms** 出现「这步没有飞机能动，换 X」 |
| M4 | 题卡显示归属人名 | 只有「这张给走到的人」 | **100% 题卡**显示当事人姓名 |
| M5 | 安全词可达屏幕 | 仅主桌，其余屏 `opacity:0` | **100% 屏幕**常驻且不被任何元素遮挡 |
| M6 | 全放过对局能否结束 | 0/40 局在 400 回合内结束 | **100% 局**在目标题卡数（快局 4 / 长夜 8）内进入收尾 |
| M7 | 落小游戏格后是否真的能玩 | 只有「玩过了」按钮 | 落格后 **≤1 次点击**进入可玩的小游戏 |
| M8 | 回顾可还原的信息 | 类型/做过/放过/原文；无归属、无时长、小游戏显示占位文案 | 6 类汇总 + 每条题卡的归属与结果 |
| M9 | 控制台未捕获错误 | 每次结束/安全词 1 条 `setSize` TypeError | 主路径 **0 条** |

## 2. 目标用户与场景

### 2.1 用户

- **一对情侣/伴侣**，两人共同使用**同一部手机**；非技术用户，不会看说明文档，靠界面自解释。
- 关系阶段与尺度偏好不同；对「露骨」「被拒绝」「被评判」敏感。**双方自愿**是前提。
- 可能一方主导操作（拿着手机的人），另一方在旁看屏幕/被要求做。
- 夜间、私密、室内（床/沙发），常伴低光；可能中途被打断（家人、消息、困了、情绪变化）。

### 2.2 关键场景

| 场景 | 描述 | 设计含义 |
|---|---|---|
| S1 第一次打开 | 不知道玩法，30 秒内要能开局 | 开局页首屏可完成；规则一屏可读；不需要注册 |
| S2 快局（工作日夜） | 8–15 分钟，想玩一点就睡 | 快局模式：2 架 + 目标 4 张题卡 + 合作收尾 |
| S3 长夜（周末） | 30–60 分钟，愿意走完整盘 | 长夜模式：4 架 + 目标 8 张题卡 + 完整棋盘 |
| S4 中途被打断 | 有人敲门/孩子醒了/一方不想继续 | 安全词/暂停随时可达；暂停不丢进度；可「今晚就到这」 |
| S5 一方明确不做某类 | 想加边界，不想解释 | 开局 6 个预设 + 自定义；**中途也能加**；边界优先 |
| S6 只想放过这一张 | 不想做但也不想破坏气氛 | 放过不惩罚：不扣心动、不阻断进军、不丢奖励、不算失败 |
| S7 网络差/没网 | 床上信号差；已装到桌面 | 离线可开局、可续玩、可收尾 |

### 2.3 非目标用户

- 单人自娱（V6 不做 AI/单人模式）、异地联机（同一部手机）、多人群玩（只支持 2 人）、未成年向内容。

## 4. 需求与验收标准

> 验收写法约定：每条 AC 都是「给定操作 → 可观察结果」。可观察结果 = 屏幕出现/不出现某段文字、某个按钮可点、某状态在 X ms 内变化、某个计数 +1、某个页面出现。凡写「可见」的，QA 必须能用截图/DOM 文本二选一证明。

### A. 开局（门厅）

| ID | 优先级 | 需求 | 可执行验收标准 |
|---|---|---|---|
| A1 | P0 | 开局页首屏即可完成开局：名字、颜色、尺度、边界、模式、开始按钮在 390×844 与 360×640 首屏内可见；若放不下，必须分步（下一步在底部固定可见） | AC-A1-1 给定 360×640 视口打开首页，无需滚动即可看到「开始」按钮（其矩形完全在视口内）；AC-A1-2 390×844 同样满足；AC-A1-3 若改为分步，第 1 步底部固定按钮文案为「下一步 1/3」且点击后进入第 2 步（不回到顶部） |
| A2 | P0 | 开局页提供「快局 / 长夜」两种模式，并显示：目标（处理几张题卡）、预计时长、飞机数 | AC-A2-1 开局页存在「快局」与「长夜」两个可选项；AC-A2-2 选择快局后，页面文本包含「目标 4 张题卡」「约 8–12 分钟」「2 架」；长夜为「目标 8 张题卡」「约 25–40 分钟」「4 架」；AC-A2-3 开始后引擎状态与所选模式一致（快局 2 架 / 长夜 4 架），且该目标在暂停页与回顾页可读到同一组数字 |
| A3 | P0 | 开局校验：名字为空、两人颜色相同、名字相同等情况在点击开始时给出行内错误，不进入对局 | AC-A3-1 清空任一名字点开始 → 不出主桌，出现「先给两个人各起一个名字」+ 对应输入框高亮；AC-A3-2 两人颜色相同（或选择时自动互斥）→ 不可能同时选中同色；AC-A3-3 名字相同 → 出现「两个名字不能一样」；AC-A3-4 修复后点开始进入主桌（`data-screen=table`） |
| A4 | P0 | 尺度四档各有一句「会发生什么」的说明（非露骨），并标出该档可用题量区间；说明不承诺具体题 | AC-A4-1 四档按钮下各有一句说明文本（每档 ≥8 字，且不含露骨词表命中）；AC-A4-2 说明文本可从 DOM 读取；AC-A4-3 尺度选择在下次开局被记住（刷新后仍选中上次档位） |
| A5 | P0 | 首次进入提供一屏「规则速览」（≤6 条），可跳过；主桌可再次打开 | AC-A5-1 首次打开（无历史）出现「玩法速览」页/弹层，内含「6 起飞」「6 可再掷」「跳/飞/进航」「击落回机坪」「放过不惩罚」「安全词随时可停」6 条文本；AC-A5-2 点「知道了」进入开局页，且本次不再出现；AC-A5-3 主桌存在「规则」入口，点击后再看到同样 6 条 |
| A6 | P0 | 存档恢复：刷新/关闭后打开，首页显示「继续今晚飞行棋」，点击回到中断处（含未处理的题卡、小游戏、暂停页） | AC-A6-1 在等待掷骰/题卡/小游戏/暂停任一状态刷新页面 → 首页出现「继续今晚飞行棋」；AC-A6-2 点击后回到同一状态（相同题卡文本 / 相同小游戏 / 相同暂停页）；AC-A6-3 该入口在无存档时不出现 |

### B. 主桌（掷骰、走子、状态）

| ID | 优先级 | 需求 | 可执行验收标准 |
|---|---|---|---|
| B1 | P0 | 掷骰结果必须同时以**文字**呈现（点数 + 是否额外掷），不能只靠 3D 骰子 | AC-B1-1 点击「掷骰」后 ≤800ms，屏幕出现形如「掷出 3」的文本；AC-B1-2 该文本在掷骰动画结束后仍保留，直到下一次掷骰；AC-B1-3 掷出 6 时文本同时包含「再掷一次」；AC-B1-4 纯 DOM 可读到点数（不依赖 canvas 截图） |
| B2 | P0 | 无合法走子时必须说明原因并自动换人 | AC-B2-1 四架都在机坪且掷出非 6 → ≤800ms 出现「没有飞机能动，换 <姓名> 掷骰」；AC-B2-2 无需额外点击即进入对方回合，回合名文本更新为该姓名；AC-B2-3 若因精确点数无法进终点，出现「进终点要刚好，这步先停」之类的具体原因（不得只换人不解释） |
| B3 | P0 | 可走子必须同时有「高亮」与「文字按钮」两种入口 | AC-B3-1 出现多个可走子时，画面上有对应的文字按钮（含颜色 + 第几架 + 从机坪起/沿航线走）；AC-B3-2 3D 棋子有可区分的高亮状态（截图对比可证）；AC-B3-3 点击文字按钮或 3D 棋子任一入口都能走出同一步（相同落点） |
| B4 | P0 | 安全词入口在**所有屏幕**常驻，且不与任何可点控件重叠 | AC-B4-1 在开局/主桌/题卡/小游戏/暂停/回顾/设置 7 个屏幕中，安全词按钮均 `opacity>0` 且可点；AC-B4-2 在 360/390/430 三种宽度下，主桌所有其他按钮的中心点做 hit-test，命中元素不得是安全词（反之亦然）；AC-B4-3 点击安全词以外的按钮不会触发安全词长按进度 |
| B5 | P0 | 主桌提供可用的「离开/暂停」入口（非结束对局），且与安全词分离 | AC-B5-1 主桌右上/左下存在「暂停」按钮，点击进入暂停页（`data-screen=pause`）；AC-B5-2 暂停页返回后对局状态不变（回合、题卡、心动值、位置一致）；AC-B5-3 该按钮 44×44 以上，中心点 hit-test 命中自身 |
| B6 | P0 | 主桌常驻状态条：当前回合姓名、已处理题卡/目标、心动值、连击数 | AC-B6-1 主桌文本区包含「<姓名> 的回合」「第 N/目标 张」「心动值 X」「连击 Y」四项；AC-B6-2 每完成一次题卡/小游戏后 ≤500ms，N 与心动值同步更新；AC-B6-3 这些文本在 360 宽下不横向溢出（无横向滚动） |
| B7 | P1 | 落点可识别：落子后显示落点格名（如「真心话格 · 第 14 格」），并允许点击格名展开该格说明 | AC-B7-1 走子结束后 ≤500ms 出现落点格名文本；AC-B7-2 点击格名显示该格类型说明（题/小游戏/跳/飞/停/进/起飞）；AC-B7-3 题卡出现时落点文本仍在（可被读到） |
| B8 | P1 | 棋盘信息可读：提供格名图例或点击查看；不依赖颜色区分类型 | AC-B8-1 主桌存在「图例」入口，展开后 8 种格类型各有文字 + 图形说明；AC-B8-2 色弱模拟（灰度截图）下，至少能通过图例 + 文字区分题格与功能格；AC-B8-3 任意格可点开显示其格名（覆盖 52 格抽查 ≥8 格） |
| B9 | P1 | 棋盘渲染失败时有可玩的降级视图 | AC-B9-1 强制禁用 WebGL 后进入主桌，出现「棋盘用列表显示」的 2D/文本视图，含所有棋子位置、当前回合、掷骰/题卡流程；AC-B9-2 降级视图下能完成一次掷骰→选子→题卡流程 |

### C. 题卡

| ID | 优先级 | 需求 | 可执行验收标准 |
|---|---|---|---|
| C1 | P0 | 每张题卡显示归属当事人姓名（cell 题 = 走到的人；击落 = 被击落方；叠机 = 两人一起；收尾 = 指定人/两人） | AC-C1-1 任意 cell 题卡 kicker 文本包含当事人姓名（两名字之一），不出现「这张给走到的人」这类无人名文案；AC-C1-2 击落卡显示被击落方姓名；AC-C1-3 叠机卡显示「两人一起」；AC-C1-4 题卡内姓名与顶部回合名一致 |
| C2 | P0 | **放过不惩罚**（红线）：点「放过」后 a) 心动值不减少（可 +3 正向）；b) 不阻断该飞机进军（进航题放过也照常进军）；c) 不丢失叠机/跳/飞奖励步；d) 连击不清零（只不增加）；e) 回顾不记为失败 | AC-C2-1 同一局面下对比「做了」与「放过」：放过后心动值 ≥ 操作前；AC-C2-2 进航题点放过后，该飞机在 ≤1 个走子动画内进入 `home:*` 航线（而不是停在原地）；AC-C2-3 叠机题放过后仍执行 +1 奖励步（或明确改为「不依赖题卡结算的固定奖励」）；AC-C2-4 连续 2 张「做了」后放过 1 张，连击显示不清零；AC-C2-5 回顾中该条只显示「今晚先放过」，不含「失败/未完成/扣分」 |
| C3 | P0 | 每次处理题卡后有明确记录反馈 | AC-C3-1 点「做了」/「放过」后 ≤500ms 出现「记下了 · 今晚第 N 张」toast；AC-C3-2 toast 与进度条同时更新；AC-C3-3 该反馈在 reduced-motion 开启时仍出现（不依赖动画） |
| C4 | P1 | 题卡不挡住棋盘关键信息，可收起 | AC-C4-1 题卡出现时，落点格名与回合名仍可读到（题卡不覆盖这两处）；AC-C4-2 题卡有「先看棋盘」收起按钮，收起后棋盘完整可见，再点「回到这张」恢复；AC-C4-3 收起/恢复不改变题卡内容与状态 |
| C5 | P1 | 题卡显示星级、来源（格子名）与类型；星级有图例解释（尺度） | AC-C5-1 题卡包含类型（真心话/大冒险/靠近/击落/叠机/收尾）、星级（★数量）、来源格名；AC-C5-2 首次出现题卡时有星级图例（1–5 星=尺度递增）可点开；AC-C5-3 不新增任何题库原文，题卡文本与 `cards.js` 一致（脚本比对） |
| C6 | P1 | 题卡提供「换一张」（有限次数，不惩罚） | AC-C6-1 每局有 N 次换卡额度（默认 2，快局/长夜一致），题卡显示剩余次数；AC-C6-2 点击「换一张」抽同池新卡，旧卡放回且不计入用过；AC-C6-3 额度为 0 时按钮置灰且不可点 |

### D. 小游戏

| ID | 优先级 | 需求 | 可执行验收标准 |
|---|---|---|---|

## 5. 玩法改动提案（P0/P1 汇总与规则细节）

> 以下「数值」是产品建议值，**不是已定案**；实现后允许通过配置调整，但验收按本节的数值断言。

### 5.1 心动值（P0，替代「没有进度」）

- 共同值 0–100，不按人分；任何操作不下降。
- 计分：题卡「做了」+8；「放过」+3（正向，表示诚实边界）；小游戏完成 +5；小游戏跳过 +0；收尾卡「做了」+10、「放过」+3；击落/叠机等棋类事件 +0（避免把「攻击对方」变成奖励）。
- 阶段文案（新增 UI 文案，非题库）：0–19「灯刚亮」/ 20–39「有点热」/ 40–59「靠近了」/ 60–79「很近了」/ 80–100「今晚可以更近」。
- 界面：主桌状态条、暂停页、回顾页三处显示同一数值与阶段名。

### 5.2 连击（P1，奖励而非惩罚）

- 两人合计连续「做了」计数；3 张触发一次「双人选卡」（2 张同尺度卡二选一，另一张放回）。
- 放过**不清零**、不扣心动；只是不增加连击。连续 6 张再触发一次（可叠加）。
- 连击数常驻显示；触发时给一次 ≤1.5s 的反馈（文本 + 轻音效），不阻塞操作。

### 5.3 二选一命运格（P1，给棋盘中段变化）

- 棋盘 2 个「命运」格；落上后同时展示 2 张不同池的卡（如真心话 + 大冒险 / 靠近 + 真心话），二选一；另一张放回池子。
- 选择/不选都不惩罚；「今晚先不选」= 直接回主桌，不扣心动、不算失败。
- 命运格处理是否计入「目标题卡数」必须在界面写明（建议不计入，作为节奏彩蛋）。
- 需用户确认是否接受新增格类型（见 Q1）。

### 5.4 合作式收尾（P0，替代「谁先送完四架谁赢」）

- 收尾条件（任一满足）：
  - 快局：处理题卡 ≥4 张，或心动值 ≥40；
  - 长夜：处理题卡 ≥8 张，或心动值 ≥80，或任一方 1 架进终点。
- 进入「今晚最后一段」：从现有 `ending` 池（mild 权重）抽 2 张收尾卡，按顺序各标归属，两人各处理一张（可放过）。
- 结束：回顾页不判定输赢；显示「今晚一起完成 N 张 / 放过 M 张 / 心动值 X」。
- 「输赢」只在长夜的可选「记录一句谁先到家」里出现，且不影响结束页（P2）。

### 5.5 今晚就到这（P0）

- 任意时刻（暂停页）可选；直接进入收尾/回顾，不判定输赢，记录全部保留。
- 与安全词的区别：安全词=立即停止当前互动（可能只是暂停）；「今晚就到这」= 主动结束并归档。两者都不惩罚。

### 5.6 今晚回顾（P0）

- 见 F2 的 6 类信息；题卡明细可展开；历史最多保留 60 局（沿用现状）。
- 隐私：只在本机；可导出 JSON；不生成公开链接。

### 5.7 快局/长夜时长（P0/P1）

- 快局：2 架、目标 4 张、预计 8–12 分钟；长夜：4 架、目标 8 张、预计 25–40 分钟。
- 依据：现状模拟（`shots/v6/analyze.json`）4 架全做平均 94.2 次掷骰 / 32.6 张题卡；2 架 46.3 次 / 15.3 张题卡，按 20s/张题 + 1.36s/次掷骰估算明显偏长，故 V6 用「目标题卡数」而不是「送完所有飞机」作为结束条件。

### 5.8 不惩罚「放过」原则（P0 红线，逐条可测）

1. 心动值不减少（可 +3）。
2. 不阻断进终点：进航题放过 → 照样进军（取消现状 `skipHomeEntryBlocksEntry` 的阻断语义）。
3. 不丢奖励步：叠机题放过 → 仍执行固定奖励步（或把奖励与题卡解耦）。
4. 连击不清零。
5. 回顾只写「今晚先放过」，不写失败/未完成/扣分。
6. 放过不延长对局：放过也计入「处理题卡数」，因此全放过局也能在目标数内收尾（修 AUD-03 的「永不结束」）。

### 5.9 P2（登记，不在 V6 范围）

| 提案 | 说明 | 为什么是 P2 |
|---|---|---|
| 回顾页生成「今晚卡片图」 | 本机生成一张可保存的图（不含露骨内容，只有日期/统计/几条原文） | 需要视觉与排版设计，且涉及隐私默认值；P0 先保证文字回顾 |
| 长夜保留「谁先到家」彩蛋 | 结束页角落一行小字，不影响收尾 | 与合作式收尾方向有张力，等 Q3 拍板 |
| 横屏/平板布局 | 大屏两栏（棋盘+题卡） | 需单独布局与测试，P0 只保竖屏 320–430 |
| 棋盘皮肤/音效主题 | 玩家可选 | 纯装饰，不影响主路径 |
| 成就/里程碑 | 「第一次放过」「连续 5 张」等 | 容易变成变相惩罚/攀比，先观察 |
| 多语言 | 英文/繁中 | 无用户需求证据，且文案含大量口语 |

| S4 走子 | 落点格名、走子中状态 | 快进（P1）、暂停、安全词 | 无落点信息 |
| S5 题卡 | 归属姓名、类型、星级、来源、做了/放过/换一张（P1）、先看棋盘（P1） | 做了、放过、暂停、安全词 | 无人名、两按钮视觉权重不同、挡住安全词 |
| S6 小游戏 | 小游戏可操作控件、跳过 | 操作、跳过、暂停、安全词 | 「玩过了」空按钮 |
| S7 收尾 | 「今晚最后一段」、收尾卡、归属 | 做了、放过、暂停 | 静默跳转、无反馈 |
| S8 回顾 | 6 类信息、题卡明细 | 保存、再开一夜、回开场 | 出现「（这一笔没有句子）」 |
| S9 暂停 | 继续、今晚就到这、看记录、加边界 | 四项 | 暂停丢失当前题卡/小游戏 |

### 6.2 动画与反馈要求（可测）

- `AN-1` 掷骰：结果文本在 **≤800ms** 出现；整段骰子动画 **≤1.6s**；动画可被「减少动画」压到 ≤100ms。
- `AN-2` 走子：单次移动动画 **≤2.0s**（多步合计）；落点格名在走子结束 **≤500ms** 出现；P1 提供「快进」跳过剩余动画。
- `AN-3` 题卡：出现动画 **≤400ms**；出现时不影响安全词可点；reduced-motion 时 ≤100ms 或无动画。
- `AN-4` 反馈：任何「做了/放过/小游戏完成/暂停」操作在 **≤500ms** 内有文本反馈（toast 或状态条变化），不依赖动画存在。
- `AN-5` 动画不阻塞输入：除 S2/S4 的防连点外，暂停与安全词在任何动画期间都可触发（安全词优先级最高）。
- `AN-6` 音效/震动可关；关闭后所有状态文本仍完整（不靠声音传达信息）。

## 7. P0 主路径与点击预算（≤20 次点击的验收路径）

**前提**：快局（2 架）、固定种子、全程选择「做了」、无 6 点连掷（验收脚本可注入骰子）。验收脚本必须断言每一步的页面/文本。

## 8. 明确不做（V6 范围外）

1. **不改题库原文、不新增露骨文案/题池**；不重写 `cards.js`；不新增「惩罚题」使用路径。

3. **不做联机/异地双人**：始终两人共用一部手机。
4. **不做第三人/AI 对手/单人模式**。
5. **不做排行榜、公开分享链接、社交功能、社区投稿**。
6. **不做广告、内购、付费墙**。
7. **不做健康/医学/避孕/安全行为指导**（安全提示仅指向「随时可停、边界优先、双方自愿」）。

9. **不替换线上域名与发布方式**（仍 GitHub Pages 同一地址）。
10. **不做多语言**（仅简体中文）。
11. **不做埋点/统计上报**；不收集任何个人数据。

13. **P0 不做横屏/平板专属布局**（P2 可评估）；竖屏 320–430 为验收范围。

## 9. 测试与验收策略（PA 视角）

1. **每条需求都有 AC**；AC 必须能被 QA 写成一条浏览器断言或引擎单测（文本/可见性/点击计数/时间阈值/数值）。
2. **引擎先行**：现有 493 条 `flight-engine.test.mjs` 必须继续全绿；新增规则（心动值、收尾条件、放过不惩罚）先在引擎层写单测，再接 UI。
3. **浏览器主路径**：按 §7 的 20 点击路径跑 3 种视口（360/390/430），断言每一步；断言 `window.onerror` 计数为 0（H6）。
4. **回归红线**（每次都跑，不允许退化）：
   - 安全词在 7 个屏幕可达且不遮挡（B4）；
   - 题卡 100% 带人名（C1）；
   - 放过不阻断进军、全放过局能收尾（C2/E3）；
   - 边界过滤 100 次抽题无命中（H5）；
   - 刷新后可续玩（A6）；
   - 断网可开局/收尾（H3）。
5. **测试钩子**：关键控件与状态需有稳定标识（如 `data-test`），另需可注入的固定骰子/固定种子用于复现；这是对 FE/BE 的交付要求（不指定实现方式）。
6. **人工验收**：真机 iOS Safari + Android Chrome 各一次（长按、安全区、PWA 安装、离线）；PA 不覆盖真机结论，QA 出具报告。
