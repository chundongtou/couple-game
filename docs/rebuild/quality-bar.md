# FullGame 正式重做 · 质量门槛与计划

> 旧 FullGame 技术原型已于 2026-11-23 下线。  
> 在下述门槛满足前，不再把任何版本称为“游戏”或“最终交付”。

## 一、旧版为什么不算游戏

- 角色是 Capsule/Sphere 拼装，没有正式模型、骨骼动画、面部或手部动作。
- 房间是方块拼装，没有真实家具、材质、灯光层次或镜头设计。
- 小游戏多数是同一套点击逻辑换参数，不是 12 种可区分的玩法。
- 手部 prefab 未稳定显示，掷骰动画只是整体位移。
- 移动端只有设备模拟，没有真机性能数据。
- 部署包 78MB，首屏与移动端体验不合格。

## 二、正式重做的质量门槛

### 垂直切片必须同时满足

1. **场景**
   - 一个完整客厅/餐桌场景，使用正式家具/材质资产。
   - 三点布光 + 环境光 + 接触阴影/后处理，WebGL 下稳定 30 FPS。
   - 镜头有明确构图：建立镜头、越肩、桌面特写、卡牌特写。

2. **角色**
   - 两个正式角色模型，带骨骼、材质和至少 8 个动画：
     - Idle、坐姿、伸手、拿牌、放下、掷骰、笑、思考。
   - 手部有抓握/释放动画；骰子与手接触点对齐。
   - 角色可换装/换色，并保存。

3. **核心循环**
   - 完整一章 12 回合：
     - 回合提示 → 掷骰 → 移动 → 抽卡 → 玩家选择 → 小游戏（可选）→ 热度/进度 → 下一回合。
   - 至少 12 张有实际选择的卡，而不是 60 张同质文本。
   - 3 个真正不同的迷你游戏，每个有独立规则、输入、反馈和失败状态。

4. **音频/反馈**
   - 环境音、骰子、卡牌、UI、成功/失败、章节结束。
   - 所有关键操作有视觉 + 听觉反馈。

5. **可访问性/本地化**
   - 中英文本、字号、减少动态、音量、键盘/触屏操作。
   - 移动端真实浏览器测试（至少 iOS Safari / Android Chrome 各一台真机或云真机）。

6. **部署**
   - 首屏加载可接受（目标 ≤ 40MB 压缩传输）。
   - 加载失败有重试/降级页。
   - 桌面与移动端均可完成一整章。

## 三、里程碑

### M1 · 资产与角色管线（先做）
- 导入正式角色（CC0 骨骼动画）与家具（CC0）。
- 建立统一材质/光照/后处理规范。
- 角色 Animator、手部挂点、骰子交互点。
- 场景灰盒 → 正式家具替换。
- 验收：一段 20 秒的“坐下 → 伸手 → 掷骰 → 收回”镜头，无穿模、手与骰子对齐。

### M2 · 核心循环
- 重写回合状态机与镜头导演。
- 卡牌选择、热度、章节进度。
- 3 个独立小游戏。
- 验收：桌面/移动端各完成 3 回合。

### M3 · 内容与表现
- 12 张有分支的卡、3 章结构、6 结局。
- 音频、照片模式、设置、存档。
- 验收：完整一章可玩，录屏无占位资产。

### M4 · 发布
- 真机性能、加载、异常、可访问性测试。
- 压缩构建、CDN/Pages 部署。
- 验收：外部用户无需说明即可完成一局。
